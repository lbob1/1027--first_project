# Pyknora 网页界面开发计划（零基础友好版）

> 版本 v1.0（规划阶段，未开始写界面代码）
> 说明：本计划用大白话编写。把 pyknora 想象成一间"知识库厨房"——后端（已建好）是厨房本身，会做菜（回答问题）；这次要造的是**前台点菜窗口**，让不用命令行的人也能舒服地点菜、看菜、查食材来源。

---

## 零、P0 需求确认决议（2026-10-30，已确认）

| 事项 | 决议 |
|---|---|
| 核心场景 | **对话 + 文档管理并重**（P4 全量保留，不裁剪） |
| 后端配合 | **允许最小配合**：仅加约 10 行跨域放行配置，不碰任何业务逻辑 |
| 使用者 | **对外演示用** → 首屏观感优先；增加：示例问题引导（观众一眼会玩）、空状态欢迎页、演示细节打磨 |
| 设备 | 电脑优先 + 手机能正常用 |
| 其余各项 | 按第三节推荐默认执行：**样式=四套主题一键切换（暖纸默认 / 纯白 / 深黑 / 彩虹·晨光），右上角切换器，记住用户选择，切换带 0.2s 平滑过渡；彩虹·晨光=移除黑底，改用四色浅调渐变底（暖杏→樱粉→雾蓝→薄荷），正文墨字对比度≥7:1（AAA）、按钮白字对光谱深档≥4.5:1（AA），光谱六色等距同族、仅约 10% 面积；每个引用来源固定一色；新增趣味×实用交互（四主题通用）：①回答来源占比条（悬停看各资料贡献）②生成中极光流光（可随时停止）③文档状态光谱环（处理中旋转→就绪绿勾）**（2026-10-30 用户追加要求）；布局=左侧栏+主对话区；引用=编号角标点击弹层；Enter 发送/Shift+Enter 换行；上传=拖拽+按钮；第一版无登录、单次会话（刷新清空）；浏览器以最新版 Chrome/Edge 为准 |

## 一、现有底子（后端已具备的能力）

| 厨房已有能力 | 大白话解释 | 界面上对应什么 |
|---|---|---|
| 对话接口 | 提问后能"一个字一个字往外蹦"地回答，并附带**引用了哪些资料** | 聊天窗口 + 回答下方的来源标注 |
| 添加文档接口 | 往知识库里放新资料 | "上传文档"按钮 |
| 文档状态接口 | 查某份资料消化好了没有 | 文档列表上的"处理中 / 就绪"小灯 |
| 登录接口 | 验证你是谁（目前较简单） | 可选的登录页 |
| 健康检查 | 报告服务是否活着 | 页角"服务正常"小绿点（可选） |

**一个已知缺口**：厨房目前没给"外带窗口"放行（专业名词叫跨域限制）。意思是从别的网页地址调用它会被浏览器拦住。解决需要动一点点后端配置（约 10 行内），或采用不改动后端的变通办法——**选哪种，见下方需求确认**。

## 二、分阶段开发计划表

时间以「需求确认完成日」为 T0，按自然日推进（确认后回填具体日期）。

| 阶段 | 做什么（大白话） | 时间节点 | 交付物 | 怎么算过关（验收标准） |
|---|---|---|---|---|
| **P0 需求确认** | 把下面第三节的确认单逐项敲定，避免做错方向 | T0 当天 | 《需求确认单》（本计划第三节勾选版） | 每一题都有明确答案或"按推荐" |
| **P1 界面草图** | 用示意图画出页面长什么样、每个区域放什么（先看草图再施工，像装修先看效果图） | T0+1 | 页面结构示意图 + 样式方向小样（2 选 1） | 你看过草图并说"就按这个来" |
| **P2 页面骨架** | 搭出能打开、能点、能切换的空页面（毛坯房：墙和门都在，还没软装） | T0+2 ~ T0+3 | 可在浏览器打开的半成品 | 所有规划中的区域都出现且位置正确，手机宽度下不变形 |
| **P3 对话打通** | 接上厨房：提问 → 逐字回答 → 点引用能看到来自哪份资料（核心体验） | T0+4 ~ T0+6 | 可真实问答的版本 | 提问后 3 秒内开始出字；回答带来源标注；点来源能看到出处名称；"停止生成"按钮可用 |
| **P4 知识库管理**（✅ 2026-10-30 完成） | 文档列表 + 上传 + 状态灯 + 删除入口（已确认全量保留） | T0+7 ~ T0+9 | 带文档管理的完整版 | 上传一份文档后能看到"处理中→就绪"变化；列表能刷新 |
| **P5 打磨与交付**（✅ 2026-10-30 完成） | 手机适配、键盘操作、**演示场景打磨**（示例问题、空状态引导、观感细节）、完整测试；交付正式成品和说明书 | T0+10 ~ T0+12 | 正式成品（可双击打开或一键启动）+ 《使用说明》+ 《验收报告》 | 逐条通过第五节总验收清单；演示路径（打开→看示例→提问→看引用→传文档）无人讲解也能走通 |

> 说明：P1 产出草图需要你过目确认后才会进入 P2；每个阶段完成都会同步进度和演示，发现阻塞第一时间上报并给备选方案。

## 三、需求确认清单（请逐项回复，可整体回复"全部按推荐"）

### A. 核心功能场景
1. 界面最核心的用途是什么？
   - 【推荐】对话问答为主：聊天窗口 + 回答下方引用来源
   - 备选：对话 + 知识库文档管理并重（P4 不裁剪）
   - 备选：极简对话框（单页面、无侧栏）
2. 一次对话需要哪些配套操作？（多选）
   - 【推荐】新建对话 / 停止生成 / 复制回答
   - 可选：历史对话列表（⚠️ 后端目前**没有**保存历史的接口，需要前端自己存或加后端配合）
   - 可选：重新生成 / 编辑后再问

### B. 目标用户与使用习惯
3. 主要给谁用？
   - 【推荐】自己和开发者，本地用，不需要登录
   - 备选：小团队多人用（要做登录页，后端已有登录接口）
   - 备选：给领导/客户演示（要更重视颜值和首屏效果）
4. 使用者的电脑水平？【推荐】会浏览器基本操作即可，界面按钮都带文字不靠猜图标。

### C. 页面结构与导航
5. 页面布局倾向？
   - 【推荐】经典双栏：左侧窄栏（知识库/设置入口）+ 右侧主对话区
   - 备选：单栏极简（像 ChatGPT 首页）
6. 需要几个页面？【推荐】聊天、文档管理 两个页面 + 可选登录页；多于 3 个页面需再讨论。

### D. 数据展示、输入与交互
7. 回答里的引用来源怎么展示？
   - 【推荐】回答末尾编号角标，点击弹出资料名称与原文片段
   - 备选：右侧固定"来源面板"同步显示
8. 提问输入框需要什么？【推荐】多行输入 + Enter 发送 / Shift+Enter 换行 / 发送中变"停止"按钮。
9. 文档上传方式？【推荐】拖拽文件到列表区 + 点击按钮选择文件；仅支持后端现有格式（txt 等，具体以实际上传接口为准）。

### E. 非功能性需求
10. 设备适配：【推荐】电脑优先，手机"能正常用"（不变形、能滚动）；若手机体验要求高请说明。
11. 样式偏好（三选一）：
    - 【推荐】A 暖纸墨色编辑风（与之前指南页同风格，沉稳耐看）
    - B 深色科技风（暗底亮字，适合技术演示）
    - C 跟随系统自动深浅色
12. 性能与兼容：【推荐】主流 Chrome/Edge 最新版即可，不追求老旧浏览器兼容。

### F. 边界条件与约束（重点确认）
13. **允许为打通连接做最小后端配合吗？**（约 10 行内的跨域放行配置，不碰业务逻辑）
    - 【推荐】允许（成品体验最完整：双击产物即可连本机后端）
    - 备选：完全不改后端 → 成品只能在开发预览模式下用，双击打开会连不上
14. **前端代码放哪里？**
    - 【推荐】`pyknora/front-end page/pyknora-web/`（延续此前"前端代码统一放此目录"的约定，不污染后端目录）
    - 备选：`pyknora/web/`（更贴近项目惯例，但需你明确授权）
15. 历史对话怎么处理（后端暂无存储接口）？
    - 【推荐】第一版先做"单次会话"，刷新即清空；历史列表列为二期
    - 备选：浏览器本地保存（只存在你自己电脑的浏览器里）
16. 需要登录页吗？【推荐】第一版不做，直接进入主界面（后端登录接口留作二期）。

## 四、名词小词典（出现过的专业词）

| 词 | 大白话 |
|---|---|
| 前端 / 后端 | 前端=你眼前能点的网页；后端=幕后干活的服务程序（pyknora 本体） |
| 接口 | 前端和后端约定好的"传话窗口"，一问一答 |
| 跨域 | 浏览器的安全规矩：A 网页默认不许随便调 B 服务的接口，需 B 明确放行 |
| 逐字回答（流式） | 回答像打字一样逐步出现，不用干等整段 |
| 构建产物 | 开发完成后生成的"正式成品文件"，双击或托管即可用 |

## 五、总验收清单（P5 逐条核对）

1. 提问后回答逐字出现，可中途停止；
2. 每条回答能看到引用了哪些资料、来自哪个文件；
3. （若确认）上传文档后能看到状态从"处理中"变"就绪"；
4. 手机宽度下打开不变形、无横向滚动；
5. 全程可用键盘操作（Tab 切换、Enter 发送）；
6. 断网/后端未启动时给出友好提示（告知怎么启动后端）；
7. 交付：正式成品 + 《使用说明》（含如何启动后端和前端）+ 《验收报告》。
